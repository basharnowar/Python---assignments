Flask Café: Code Review (no rewrite yet)
1. Review Summary

The structure is good. Routes are clear, and the POST → redirect → summary flow is the correct pattern, so refreshing the summary page won’t resubmit an order. You also reassign session["orders"] = orders after appending, which is what makes Flask save the change. Jinja’s {{ }} escapes text automatically, so item names are safe to display.

The weak spots are what happens when something unexpected arrives: a missing session, a bad quantity, or a changed hidden input. There are also a few small duplication and display problems.

Count: 4 Must Fix, 6 Should Consider, 3 Optional.

2. Issues Found

Must Fix

1-Session keys are assumed to exist.
-app.py, summary(): session["orders"], session["total"]
-app.py, saveOrder(): session["orders"], session["total"] += ...
-Only home() creates these keys.

2-/order accepts GET but only works with POST.
-app.py: @app.route("/order", methods=["GET", "POST"])
-The function reads request.form[...] right away.

3-The price is trusted from a hidden input.
-index.html: <input type="hidden" name="price" value="2" />
-app.py: price = float(request.form["price"])

4-Quantity (and item) are not validated.
-app.py: quantity = int(request.form["quantity"])
-index.html: <input type="number" name="quantity" value="1" /> has no min, max or required.

Should Consider

5-/clear changes data through a GET link.
-app.py: @app.route("/clear")
-summary.html: <a href="/clear">Clear All Orders</a>

6-The total is stored separately, and the math lives in two places.
-app.py: session["total"] += quantity * price
-summary.html: {{ order.price * order.quantity }}

7-Money displays inconsistently.
-summary.html: ${{ order.price }} and ${{ total }} show $2.0 and $9.0, while the menu shows $2.00.

8-The menu is duplicated.
-index.html: three nearly identical <section> and form blocks, and each price is written twice ($2.00 and value="2").

9-Paths are hardcoded.
-/static/style.css, action="/order", href="/summary", redirect("/summary").

10-Adding the same item twice creates separate rows. This one is a design decision.
-app.py: orders.append(order) always adds a new entry.

Optional

11-Naming. saveOrder is camelCase, while Python uses save_order. Each entry in orders is really one line item, not an order.

12-Fixed width on small screens. style.css: .container { width: 700px; }

13-Secret key. app.py: app.secret_key = "review-key"

3. Why Each Issue Matters

1-If someone opens /summary directly (a bookmark, a cleared cookie, or an old cookie after you change the secret key), session["orders"] raises a KeyError and they get a 500 error. The same thing happens if they submit an order from a stale page. Relying on home() to prepare the session means the app only works if pages are visited in one order.

2-Typing /order in the address bar sends a GET request. The route allows it but has no GET behavior, so it fails with a 400 “Bad Request”. A route that declares a method should handle it, or not declare it.

3-Hidden inputs are only hidden from the screen. Anyone can edit the value in the browser’s dev tools and submit price=0.01, or even a negative price. Hidden inputs are fine for telling the server which item, but the server should decide what things cost.

4-An empty field or 3.5 makes int() raise a ValueError and crash. The server also accepts 0, -5 (which lowers the total) and absurdly large numbers. type="number" only helps the user’s browser, and requests can be sent without that form. The server must check for itself.

5-A GET request should only read data. Links can be clicked by accident, prefetched by browsers, or opened by another page, and any of those would wipe the order. A destructive action should require a POST.

6-The total is something you can always work out from orders. Storing it separately means two things to keep in sync, and the home() setup code and the missing-key crashes both come partly from this. Splitting the math between Python and the template makes the rules harder to find.

7-The menu says $2.00, but the summary says $2.0, and some totals could show unexpected decimals. It’s a visible polish and correctness issue.

8-Changing a price means editing two spots, and the displayed price and the hidden price can drift apart. Adding a menu item means copying a whole block. This is closely tied to issue 3.

9-Hardcoded paths work, but renaming a route means hunting through several files. Using url_for is also the convention you were taught for static files.

10-This isn’t wrong, but ordering two Teas in two clicks gives two rows, which may not be what you want. Since the whole session lives in a cookie, the list also keeps growing, and browsers can silently drop cookies over about 4 KB.

11-This is readability only. Clear names help you and your instructor follow the code.

12-On a phone narrower than 700px the page scrolls sideways.

13-Session data is stored in the cookie and signed with this key. Anyone who knows the key can forge a session. A short, guessable key is fine while learning but would be risky in a real project.

4. Suggested Direction
1-Stop depending on home() to set up the session. Read orders from the session with a default of an empty list (the .get() method), so “missing” simply means “empty”. The setup block in home() can then go away.

2-Decide that /order only processes the form, and allow POST only. A direct visit then gives “405 Method Not Allowed”, which is the honest answer.

3-Keep the menu in one Python dictionary (item name → price). The hidden input sends only the item name, and the route looks up the price itself. If the name isn’t in the menu, reject the request.

4-Convert the quantity inside a try/except for ValueError (or check that the text is digits), then check it against a range you choose (for example 1 to 20). If anything is invalid, send the user back to the menu. Also add min, max and required to the HTML input, as a convenience only.

5-Turn “Clear All Orders” into a small form with a button, make /clear POST-only, and keep the redirect after it.

6-Calculate the total inside summary() by looping over orders, and stop storing total in the session. Do the subtotal math in the same place so the logic lives in one spot.

7-Use Jinja’s format filter on every money value so they all show two decimals, like the menu.

8-After item 3 is done, pass the menu to the template and use a {% for %} loop, so there is one form block and one place for prices. Do 3 and 8 together.

9-Use url_for('static', filename=...) for the stylesheet. Using url_for for your own routes and redirects is a nice extra.

10-Decision for you: merge repeated items into one row, or keep separate rows. If you merge, you’ll need to check whether the item is already in the list. I’d add a quantity limit either way.

11-Rename saveOrder to save_order, and consider item or order_items for the per-row variable.

12-Change width to max-width (keeping width: 100%).

13-For now, a longer random-looking string is enough, and just remember never to put anything private in the session.
